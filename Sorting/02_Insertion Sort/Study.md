# 삽입 정렬 (Insertion Sort)

## 1. 삽입 정렬이란?

삽입 정렬은 **현재 원소를 이미 정렬된 구간의 알맞은 위치에 삽입**하는 정렬 알고리즘이다.

배열의 **첫 번째 원소는 정렬되어 있다고 가정**하고, 두 번째 원소부터 하나씩 왼쪽의 정렬된 구간에 끼워 넣는다.

- 왼쪽: 정렬이 완료된 구간
- 오른쪽: 아직 정렬하지 않은 구간
- 현재 원소보다 큰 값은 오른쪽으로 한 칸씩 이동한다.
- 빈자리에 현재 원소를 삽입하면 정렬된 구간이 한 칸 늘어난다.

---

## 2. 동작 과정

다음 배열을 오름차순으로 정렬한다고 가정하자.

```text
[5, 3, 1, 4, 2]
```

처음에는 `5` 하나만 정렬된 상태로 취급한다.

**1회전 — `3` 삽입**

```text
[5 | 3, 1, 4, 2]
 → 5를 오른쪽으로 이동
[3, 5 | 1, 4, 2]
```

**2회전 — `1` 삽입**

```text
[3, 5 | 1, 4, 2]
 → 5, 3을 오른쪽으로 이동
[1, 3, 5 | 4, 2]
```

**3회전 — `4` 삽입**

```text
[1, 3, 5 | 4, 2]
 → 5를 오른쪽으로 이동
[1, 3, 4, 5 | 2]
```

**4회전 — `2` 삽입**

```text
[1, 3, 4, 5 | 2]
 → 5, 4, 3을 오른쪽으로 이동
[1, 2, 3, 4, 5]
```

`|`는 정렬된 구간과 아직 정렬하지 않은 구간의 경계를 나타낸다. **매 회전이 끝날 때마다 왼쪽 구간은 항상 정렬되어 있다.**

## 3. C++ 구현

```cpp
#include <iostream>

int main()
{
    int arr[] = {5, 3, 1, 4, 2};
    int n = 5;

    for (int i = 1; i < n; ++i)
    {
        int key = arr[i];
        int j = i - 1;

        while (j >= 0 && arr[j] > key)
        {
            arr[j + 1] = arr[j];
            --j;
        }

        arr[j + 1] = key;
    }

    for (int x : arr)
    {
        std::cout << x << ' ';
    }
}
```

출력:

```text
1 2 3 4 5
```

### 주요 변수

| 변수 | 역할 |
| --- | --- |
| `i` | 정렬된 구간에 새로 삽입할 원소의 인덱스 |
| `key` | 삽입할 값을 임시로 보관 |
| `j` | 정렬된 구간을 오른쪽에서 왼쪽으로 비교하는 인덱스 |

### 코드 분석

**① `i = 1`부터 시작**

```cpp
for (int i = 1; i < n; ++i)
```

첫 번째 원소 `arr[0]`은 원소가 하나뿐이므로 이미 정렬된 상태로 본다. 따라서 두 번째 원소부터 삽입을 시작한다.

**② 삽입할 값을 따로 저장**

```cpp
int key = arr[i];
int j = i - 1;
```

기존 원소를 오른쪽으로 덮어쓰며 이동시키기 때문에 `arr[i]`의 원래 값을 `key`에 보관해야 한다. `j`는 현재 원소의 바로 왼쪽에서 시작한다.

**③ 더 큰 원소를 오른쪽으로 이동**

```cpp
while (j >= 0 && arr[j] > key)
{
    arr[j + 1] = arr[j];
    --j;
}
```

- `j >= 0`: 배열의 왼쪽 범위를 벗어나지 않았는지 확인한다.
- `arr[j] > key`: 왼쪽 원소가 `key`보다 클 때만 이동한다.
- `arr[j + 1] = arr[j]`: 값을 교환하는 것이 아니라 **오른쪽 칸에 복사**한다.
- `--j`: 그다음 왼쪽 원소와 비교한다.

C++의 `&&`는 왼쪽 조건이 거짓이면 오른쪽을 평가하지 않는다. 따라서 `j`가 `-1`일 때 `arr[-1]`에 접근하지 않는다.

**④ 빈자리에 `key` 삽입**

```cpp
arr[j + 1] = key;
```

반복문은 `j`가 `-1`이 되거나, `arr[j] <= key`인 지점에서 멈춘다. 따라서 실제 삽입할 자리는 **`j`의 바로 오른쪽인 `j + 1`**이다.

## 4. while문 내부에서 실제로 일어나는 일

`[3, 5, 1, 4, 2]`에서 `1`을 삽입하는 상황을 자세히 보자.

```text
초기 상태
arr = [3, 5, 1, 4, 2]
key = 1, j = 1

5 > 1 → 5를 오른쪽으로 복사
arr = [3, 5, 5, 4, 2]
j = 0

3 > 1 → 3을 오른쪽으로 복사
arr = [3, 3, 5, 4, 2]
j = -1

j >= 0이 거짓 → while 종료
arr[j + 1] = arr[0] = 1

결과
arr = [1, 3, 5, 4, 2]
```

중간에 `5`나 `3`이 두 번 나타나는 것은 **값을 오른쪽으로 복사하는 과정**이기 때문이다. 삽입할 `1`은 `key`에 보관되어 있으므로 마지막에 올바른 자리에 넣을 수 있다.

> 삽입 정렬의 핵심: **값 저장 → 왼쪽 비교 → 큰 값 이동 → 빈자리에 삽입**

## 5. 시간 복잡도

| 경우 | 시간 복잡도 | 이유 |
| --- | --- | --- |
| 최선 | `O(n)` | 이미 정렬되어 있어 각 원소를 한 번만 비교 |
| 평균 | `O(n²)` | 앞쪽의 여러 원소를 비교하고 이동 |
| 최악 | `O(n²)` | 역순 배열에서 거의 모든 앞쪽 원소를 이동 |

이미 오름차순인 배열에서는 `while` 조건이 곧바로 거짓이 되어 이동이 발생하지 않는다.

반대로 역순 배열에서는 `i`번째 회전마다 최대 `i`개의 원소를 이동한다.

```text
1 + 2 + 3 + ... + (n - 1)
= n(n - 1) / 2
= O(n²)
```

따라서 **거의 정렬된 데이터에서 특히 유리**하지만, 원소 수가 많고 순서가 뒤섞인 배열에서는 비효율적일 수 있다.

## 6. 공간 복잡도와 안정성

- **공간 복잡도: `O(1)`** — `key`, `i`, `j` 등 일정한 수의 변수만 추가로 사용한다.
- **제자리 정렬(In-place Sort): O** — 별도의 배열 없이 원본 배열 안에서 정렬한다.
- **안정 정렬(Stable Sort): O** — 같은 값을 가진 원소들의 기존 상대적 순서를 유지한다.

안정 정렬이 가능한 이유는 조건이 `arr[j] > key`이기 때문이다. 두 값이 같으면 이동시키지 않으므로 기존 순서가 바뀌지 않는다. 조건을 `>=`로 바꾸면 이 성질이 깨질 수 있다.

---

## 7. 특징 정리

| 항목 | 삽입 정렬 |
| --- | --- |
| 기본 원리 | 정렬된 구간에 현재 원소 삽입 |
| 주요 연산 | 비교 후 오른쪽으로 한 칸 이동 |
| 최선 시간 | `O(n)` |
| 평균·최악 시간 | `O(n²)` |
| 추가 공간 | `O(1)` |
| 안정 정렬 | O |
| 잘 맞는 상황 | 크기가 작거나 거의 정렬된 배열 |

**요약:** 삽입 정렬은 왼쪽의 정렬된 구간을 유지하면서 현재 값을 올바른 위치에 넣는 방식이다. `key`, `j`, `arr[j + 1]`의 역할을 이해하는 것이 가장 중요하다.
